# 客户信息查询接口说明

> **对应功能**：根据客户编号查询企业实际控制人姓名、管户权校验
>
> **数据来源**：`kjjr_ai_sxd_profile` 表（善新贷材料生成结果表）

---

## 一、接口说明

### 1.1 请求

```
POST /techfin/sxd/controller-name
Content-Type: application/json
```

**请求体：**

```json
{
  "taskId": "TASK-3bc23bbb64da475681c771f5306907b5",
  "cstId": "442025623335526905"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `taskId` | String | 是 | 任务 ID，格式 `TASK-<32位hex>`，用于查询 `kjjr_ai_sxd_record.has_ownership` 校验管户权 |
| `cstId` | String | 是 | 客户编号，用于查询 `kjjr_ai_sxd_profile` 实控人姓名 |

**成功响应（有管户权）：**

```json
{
  "code": 0,
  "msg": "成功",
  "data": "王美"
}
```

> `data` 字段直接返回实控人姓名（`actCntlrNm`）字符串。

**成功响应（无管户权）：**

```json
{
  "code": 0,
  "msg": "成功",
  "data": ""
}
```

> 用 `taskId` 查询 `kjjr_ai_sxd_record`，`has_ownership = '1'` 时返回姓名，否则（含 `0`、未设置）返回空字符串。无论是否有管户权，都将查询到的实控人姓名回填到 `kjjr_ai_sxd_record.act_cntlr_nm`。

**异常响应（客户编号不存在）：**

```json
{
  "code": -1,
  "msg": "客户编号 [442025623335526905] 不存在",
  "data": null
}
```

### 1.2 处理流程

```
① 接收请求 → 校验 taskId、cstId 非空
         → 用 cstId 查询 kjjr_ai_sxd_profile 表（以 cstId 为主键）获取 actCntlrNm
         → 用 taskId 查询 kjjr_ai_sxd_record（以 taskId 为主键）获取 has_ownership
         → 将查询到的 actCntlrNm 回填到 kjjr_ai_sxd_record.act_cntlr_nm
         → has_ownership = '1' → 返回 actCntlrNm
         → has_ownership 为 '0' 或未设置 → 返回空字符串
         → 查不到 kjjr_ai_sxd_profile 时抛出 CUSTOMER_NOT_FOUND
         → 查不到 kjjr_ai_sxd_record 时抛出 TASK_NOT_FOUND
```

---

### 1.3 确认/修改实控人姓名

用户在页面确认或修改实控人姓名后，回填到 `kjjr_ai_sxd_record` 表。

```
PUT /techfin/sxd/application-record/controller-name
Content-Type: application/json
```

**请求体：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `taskId` | String | 是 | 任务 ID（submit-materials 返回的 taskId） |
| `actCntlrNm` | String | 是 | 实际控制人姓名（可修改） |

**请求示例：**

```json
{
  "taskId": "TASK-abc123...",
  "actCntlrNm": "王美"
}
```

**成功响应：**

```json
{
  "code": 0,
  "msg": "实际控制人确认成功",
  "data": null
}
```

> 根据 `taskId` 找到 `kjjr_ai_sxd_record` 记录，更新 `actCntlrNm` 和 `updatedAt` 字段。

---

### 1.4 管户权校验

校验当前登录用户是否拥有该任务对应客户的管户权。

```
POST /techfin/sxd/cust-ownership
Content-Type: application/json
```

**请求体：**

```json
{
  "taskId": "TASK-abc123...",
  "cstId": "CST0180779984"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `taskId` | String | 是 | 任务 ID，格式 `TASK-<32位hex>` |
| `cstId` | String | 是 | 客户编号 |

> 请求头需携带 `Authorization: Bearer <encrypted-token>`，后端解密得到 `userAccount`（Base64 解码后为实际账号）存入 `request.setAttribute("userAccount", ...)`。

**成功响应：**

```json
{
  "code": 0,
  "msg": "成功",
  "data": true
}
```

| 字段 | 说明 |
|------|------|
| `data` | 是否拥有管户权（按管户权判断逻辑返回 true/false） |

**处理流程：**

```
① 接收请求 → TokenInterceptor 解密 Authorization 头获取 userAccount（Base64 解码后存入 request attribute "userAccount"）
         → 校验 taskId、cstId 非空

② 根据 userAccount（对应 msp_user.account）查询用户 → 得到 staff_code、role_id（一个或多个，逗号分隔）、dept_id（仅一个）

③ 通过 dept_id 查询 msp_dept → 得到 institution_no

④ 判断一：role_id 含「分行经办人员(94)」 且 institution_no = 443536363（科技金融创新中心）
         → 两者都满足 → 管户权 true

⑤ 判断二：用 kjjr_ai_sxd_profile.cst_mngacc_inst_supr_insid（管户支行编号）匹配 institution_no
         → 一致 且 role_id 含「支行科室负责人(92)」 → 管户权 true
         → 不一致，或一致但非支行科室负责人 → 进入判断三

⑥ 判断三：用 kjjr_ai_sxd_profile.cst_mngacc_cstmgr_id（管户客户经理编号）匹配 staff_code
         → 一致 → 管户权 true

⑦ 其余情况 → 管户权 false

⑧ 结果写入 kjjr_ai_sxd_record.has_ownership（1-有，0-无），并返回 true/false
```

> `role_id` 为逗号分隔的多角色 ID，判断"是否包含某角色"时遍历集合匹配；`dept_id` 仅为单个值。

## 二、数据来源

### 数据表

| 表名 | 说明 |
|------|------|
| `kjjr_ai_sxd_profile` | 善新贷材料生成结果表，由上游 ETL 每日同步 |
| `msp_user` | 用户表，按 `account` 查询 `staff_code`、`role_id`、`dept_id` |
| `msp_dept` | 部门/机构表，按 `dept_id` 查询 `institution_no` |
| `kjjr_ai_sxd_record` | 申请记录表，管户权校验结果写入 `has_ownership` |

### 涉及字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `cst_id` | VARCHAR(200) | 客户编号（查询条件） |
| `cst_nm` | VARCHAR(500) | 客户名称 |
| `act_cntlr_nm` | VARCHAR(200) | 实控人姓名（返回值） |
| `cst_mngacc_cstmgr_id` | VARCHAR(200) | 管户客户经理编号（匹配 `msp_user.staff_code`） |
| `cst_mngacc_inst_supr_insid` | VARCHAR(200) | 管户支行编号（匹配 `msp_dept.institution_no`） |
| `data_bsn_dt` | DATE | 数据业务日期 |

> `cst_id` 为 `kjjr_ai_sxd_profile` 表的主键，每条客户编号对应唯一一条记录。

## 四、错误码一览

| 错误码 | 触发条件 | HTTP 状态码 |
|--------|---------|------------|
| `PARAM_MISSING` | `cstId` 或 `taskId` 或 `actCntlrNm` 为空 | 400 |
| `TASK_NOT_FOUND` | 任务 ID 对应的 `kjjr_ai_sxd_record` 不存在 | 400 |
| `CUSTOMER_NO_MISSING` | 任务对应的 `kjjr_ai_sxd_record` 中未找到客户编号 | 400 |
