# 报告生成功能说明

> **功能入口**：要素提取 completed=true 后，前端下载 Word 报告文档
>
> **前置条件**：已完成要素提取（`GET /sxd/extract-status/{taskId}` 返回 `completed: true`）
>
> **关联文档**：[`要素提取功能说明.md`](要素提取功能说明.md)

---

## 一、核心业务逻辑

### 1.1 背景

要素提取完成后，系统已从上传的财务报表中提取了结构化的财务数据，同时商业计划书的提取文本已缓存至 `kjjr_ai_sxd_extract_data` 表。报告生成功能从这些提取数据中聚合财务报表各期间的资产负债表关键科目和利润表关键科目，同时查询**客户基本信息**（`kjjr_ai_sxd_profile` 表）、**实控人姓名和管户权**（`kjjr_ai_sxd_record` 表）和**商业计划书提取文本**（`kjjr_ai_sxd_extract_data` 表），通过 **Apache POI** 组件向 Word 模板文档的占位符位置插入数据，生成 `.docx` 格式的报告文件下载。

> **前置条件**：生成报告前需先调用 `POST /sxd/cust-ownership` 校验管户权，该接口会将结果写入 `kjjr_ai_sxd_record.has_ownership`。若 `has_ownership=0` 或未设置，报告中所有从 `kjjr_ai_sxd_profile` 读取的字段占位符将被替换为空字符串（`{{act_cntlr_nm}}` 除外，它始终从 `kjjr_ai_sxd_record.act_cntlr_nm` 读取，不受管户权影响）。

### 1.2 生成报告接口

```
POST /techfin/sxd/report
Content-Type: application/json
```

**请求体：**

```json
{
  "taskId": "TASK-abc123...",
  "cstId": "CST0180779984"
}
```

| 字段       | 类型     | 必填 | 说明                              |
| -------- | ------ | -- | ------------------------------- |
| `taskId` | String | 是  | 提交资料返回的任务 ID，格式 `TASK-<32位hex>` |
| `cstId`  | String | 是  | 客户编号                            |

**成功响应：** 返回 `.docx` 文件下载（`Content-Type: application/vnd.openxmlformats-officedocument.wordprocessingml.document`），文件名 `善新贷客户关键信息调查报告.docx`。

> - **`if_loan`**：`1` 填充「存量」，`0` 填充「新增」。
> - **`if_yuqi`/`ltgtrltd_ind`/`if_rad_alarm`**：`1` 填充「是」，`0` 填充「否」。

> **管户权过滤**：`{{act_cntlr_nm}}` 从 `kjjr_ai_sxd_record.act_cntlr_nm` 读取（非 `kjjr_ai_sxd_profile`）。若 `kjjr_ai_sxd_record.has_ownership=0`，以上从`kjjr_ai_sxd_profile`表读取所有的字段占位符替换为空字符串（除了act_cntlr_nm是从 `kjjr_ai_sxd_record.act_cntlr_nm` 读取的）。`has_ownership=1` 时按正常值填充，`has_ownership=0` 或未设置时替换为空。

| 占位符                              | 说明                      | 生成句式                                                                   | 兜底句式（生成不出来时）                         |
| -------------------------------- | ----------------------- | ---------------------------------------------------------------------- | ------------------------------------ |
| `{{profile_main_business}}`      | 主营业务概况                  | `主营业务为 XXX`，一句话，不罗列产品清单                                                | `主营业务为 XX`                           |
| `{{profile_downstream}}`         | 下游主要服务                  | `下游主要服务 XXX 等行业头部企业`，XXX 是**材料里确实出现过的下游客户企业名**（如「长电科技、通富微电」），**不是行业名** | `下游主要服务 XX 等行业头部企业`                  |
| `{{profile_highlights}}`         | 企业亮点描述                  | `企业亮点描述：XXX`，不许编造投资方/头衔/荣誉                                             | `企业亮点描述（如有，包括但不限于创投投资、人才、技术国产替代等情况）` |

> 四个占位符在模板里**各自独占一段、不带任何前后缀**。每段正文都由模型输出**完整句子**（含「主营业务为」「下游主要服务」「企业亮点描述：」「主要应用情况：」等引导词），因此不存在"半截话"拼接问题。

> ⚠️ **句末标点有两套规则**（2026-10-08 / 10-09 定）：
>
> - **前三个**占位符填进去的文本**一律不带标点**：不论来自模型还是兜底句式，结尾的 `。`/`；`/`，` 等都会被剥掉 —— 标点交给模板排版决定。
> - **第四个**（`{{profile_patent_application}}`）**保留句末「。」，且两句各一个**。这一条不靠模型自觉：Java 先把模型给的两段各自剥净句末标点，再统一补「。」，所以既不会出现「。。」也不会漏句号。两段都拿不到时得到的正是用户给的模板句式（其中「是/否」**刻意保留**，等于把选择题留给人工勾选）。
>
> 只剥**结尾**的标点，正文中间的标点（如「企业亮点描述：」的冒号）不动，`）`/`】` 这类右括号也保留（兜底句式 3 正是以 `）` 收尾）。

> ⚠️ **特殊情况一律回落成"模板句式"而不是留空**（2026-10-08 定）：材料为空、提示词不可用、调用失败、模型某行没产出内容 —— 该字段就填成上表最后一列那句话，把 `XX` / `XXX` 留成人工补写的空格。这样报告里始终看得见"这里原本该写什么、由谁补"，不会出现不知所云的空段。（底层 `LlmSectionWriter` 的"失败留空"不变，是这里在它之后再兜一层默认值。）
>
> 第四个字段的两句**各自独立兜底**：应用情况缺失时只替换那一句，创投结论照常输出，反之亦然。

| 占位符                                | 说明         | 数据来源                                                                                        |
| ---------------------------------- | ---------- | ------------------------------------------------------------------------------------------- |
| `{{dib_director_keyresume}}`       | 实际控制人及团队简介 | 缓存表 `dib_director_keyresume`，经**大模型二次总结编辑**成"实际控制人情况 + 核心团队情况"固定样式                          |

`{{dib_manage_business_overview}}` 不是某张表的原文，而是把**多张表**的提取文本交给大模型做一次「二次总结编辑」后的结果。2026-10-08 由原先并列的两个占位符（`{{dib_manage_business_and_products}}`、`{{dib_manage_business_circumstance}}`）合并而来；同日素材范围**由 2 段扩到 7 段**。

### 1.4 判断逻辑

#### 确定使用的资产负债表类型

对每个财务报表文档，通过以下步骤确定使用哪个表查询数据：

```
┌─ 查询 docTableExtractState/{docId}
│
├─ 是否有报表附注信息（dib_intervening_y_auditreport_jh）?
│   ├─ 是 → 查询"财务报表口径"（item_value）
│   │   ├─ "1"(单一) → 使用母公司资产负债表（dib_fin_balance_parent）
│   │   └─ "2"(合并) → 使用合并资产负债表（dib_fin_balance）
│   │
│   └─ 否 → 直接比较资产负债表提取状态
│       ├─ 仅合并表为Y → 使用合并表（dib_fin_balance）
│       ├─ 仅母公司表为Y → 使用母公司表（dib_fin_balance_parent）
│       └─ 均为Y或均非Y → 默认使用合并表（dib_fin_balance）
│
└─ → 调用 queryData（{docId, tableName}）查询科目数据
```

#### 数据聚合规则

1. 每个文档对应一个 `report_date`，查询到的 `current_amount` 即为该日期的科目值
2. 多个文档（不同 `report_date`）的数据按科目名称 `item` 合并，形成完整的多日期表格
3. 表格列按 `report_date` **降序排列**，最新日期列在最前面
4. 未匹配到数据的科目显示 `-`；`null` 值经 `formatAmount()`、`formatGrowthRate()`、`formatRatio()` 等格式化方法统一转为 `-`
5. 查询某文档失败或返回空数组时，**仍保留该日期列**（列头存在），数据格显示 `-`，确保与其它期对齐、避免整列丢失
6. 利用 `lastAmount`（上期金额）补全缺失的上一期日期列：若某文档只有 `report_date` 对应的当期数据，但 `lastAmount` 有值且该日期列尚未存在，则自动用 `lastAmount` 补充一列（适用资产负债表和利润表）

└─ → 调用 queryData（{docId, tableName}）查询科目数据

> 财务报表口径的判断逻辑与资产负债表完全一致（共享 `dib_intervening_y_auditreport_jh` 表口径），同一个文档的资产负债表和利润表会选择同一口径（单一→母公司表，合并→合并表）。

## 二、处理流程

```
┌─ 前端点击"生成报告"
│
├─ 后端处理流程：
│   ① 查 kjjr_ai_sxd_record → 校验 taskId 存在，**校验传入 cstId 与记录中 cst_id 一致**（防止越权查询其他客户信息）
│   ② 查 kjjr_ai_sxd_profile → 获取客户基本信息
│   ③ 根据 taskId 查 kjjr_ai_sxd_doc → 获取财务报表 docId 列表
│   ④ 对每个 docId：
│      ├─ docTableExtractState（单次调用）→ 同时确定合并/母公司表
│      ├─ queryData(资产负债表) → 获取科目
│      └─ queryData(利润表) → 获取科目
│   ⑤ 按科目和日期聚合数据
│   ⑥ 从 kjjr_ai_sxd_extract_data 缓存表读取商业计划书提取文本
│   ⑦ 大模型生成「客户基本概况」四字段：主营业务概况 / 下游主要服务 / 企业亮点描述 / 专利技术应用情况及创投投资情况
│      ├─ 正常 → 采用模型输出（五行，各自带「主营业务为」「下游主要服务」「企业亮点描述：」「主要应用情况：」引导词）
│      │          第四字段由 `APPLY#` + `INVEST#` 两行拼成 `主要应用情况：…。{有/无}创投机构投资…。`（句号由 Java 补）
│      ├─ 某行没产出（材料里没亮点 / 没有具体下游企业名 / 没提专利怎么用 / 没提投资方 / 标签被改写）→ 该行回落成兜底句式（其余照常）
│      │          第四字段的两句各自独立兜底（应用情况缺→只换那半句）
│      └─ 异常（调用失败 / 提示词缺失 / 返回空内容 / 7 段材料全空）→ 四字段全回落成兜底句式（打 ERROR 日志）
│      ⇒ 兜底句式 = `主营业务为 XX` / `下游主要服务 XX 等行业头部企业` / `企业亮点描述（如有，包括但不限于创投投资、人才、技术国产替代等情况）` /
│         `主要应用情况：XXX。是/否有创投机构投资，创投机构名称为XXX。`（XX / XXX 留作人工补充，「是/否」留给人工勾选）
│      句末标点两套规则：前三个字段一律不带标点（`stripTrailingPunct` 统一剥掉，模型写了句号也照剥）；
│      第四字段反过来必须带「。」，由 `buildPatentApplication` 统一补（先剥净再补，绝不会出现「。。」）
│      四键恒定落盘、值绝不为空 ⇒ 报告里不会出现空段，也不会残留 `{{...}}` 字面量
│      异常不中断报告生成
│      ⚠️ 必须排在第 ⑩ 步之前：两者素材同源，第 ⑩ 步会把来源键置空
│   ⑧ 读 sxd_record.act_cntlr_nm（实控人姓名），供下一步比对
│   ⑨ 大模型二次总结：人员简历 + 实控人姓名 → 「实际控制人及团队简介」
│      ├─ 正常 → 采用模型输出（第1行实际控制人情况 / 第2行核心团队情况：/ 之后每人一段）
│      └─ 异常（调用失败 / 提示词缺失 / 返回空内容）→ 该段落留空（打 ERROR 日志）
│      异常不中断报告生成
│   ⑩ 大模型二次总结：7 段提取文本（公司介绍/主营业务和产品/经营情况介绍/研发成果与转化情况/
│      竞争优势介绍/发展战略情况/行业发展情况）→ 一段「企业主营业务情况」
│      ├─ 正常 → 采用模型输出（一段连续文字，仍只覆盖原有七项内容）
│      ├─ 全部素材为空 → 不调用大模型，占位符置空
│      └─ 异常（调用失败 / 提示词缺失 / 返回空内容）→ 该段落留空（打 ERROR 日志）
│      异常不中断报告生成
│      ⚠️ 本步会把 7 个来源键全部置空 ⇒ 必须晚于第 ⑦ 步（客户基本概况各字段读的正是同一批 7 段素材）
│   ⑪ 筛出两张表里增长率绝对值 > 30% 的科目 → 大模型写成「异常财务数据说明」
│      ├─ 有超阈值科目 → 采用模型输出（一个科目一行）
│      ├─ 无超阈值科目 → 不调用大模型，占位符置空
│      └─ 异常（调用失败 / 提示词缺失 / 返回空内容）→ 该段落留空（打 ERROR 日志）
│      异常不中断报告生成
│   ⑫ 加载 Word 模板文件 → 替换 {{占位符}}
│      ├─ has_ownership=1  → 所有字段正常填充
│      └─ has_ownership=0 → 22 个敏感字段替换为空
│   ⑬ 删除 kjjr_ai_sxd_doc 中该 task_id 的文档记录
│   ⑭ 删除 kjjr_ai_sxd_extract_data 中该 task_id 的缓存记录
│   ⑮ 更新 kjjr_ai_sxd_record.status = 1
│   ⑯ 调用外部 API 删除系统中的文档（POST /api/extract/open/doc/delete/{docId}）
│   ⑭ 返回 .docx 文件字节流
│
└─ 前端下载"善新贷客户关键信息调查报告.docx"
```

### 模板替换机制

报告基于 Word 模板（`.docx`）生成，模板中的占位符格式为 `{{占位符名称}}`：

- **客户信息字段**：`{{cst_nm}}`、`{{credit_code}}` 等 34 个占位符 → 替换为字段值
- **企业基本信息字段**：`{{cst_nm}}`、`{{credit_code}}` 等 34 个占位符 → 从 `kjjr_ai_sxd_profile` / `kjjr_ai_sxd_record` 取值
- **商业计划书提取文本**：`{{dib_director_keyresume}}`、`{{dib_manage_business_overview}}` 2 个占位符 → 分别替换为「人员简历经大模型二次总结后的实际控制人及团队简介」、「**7 段** BP 提取文本经大模型汇总后的企业主营业务情况」
- **客户基本概况四字段**：`{{profile_main_business}}`、`{{profile_downstream}}`、`{{profile_highlights}}`、`{{profile_patent_application}}` → 由大模型依据 BP **7 段**提取文本生成（与「企业主营业务情况」共用 `BpExtractSources.SOURCES`；**注意这四个不受管户权过滤影响**）
- **资产负债表表格**：`{{balance_sheet_key_items}}` → 在该位置插入 XWPFTable
- **利润表表格**：`{{profit_sheet_key_items}}` → 在该位置插入 XWPFTable
- **异常财务数据说明**：`{{abnormal_finance_description}}` → 替换为大模型撰写的超阈值科目变化说明（一个科目一行）

代码通过 `XmlCursor` 在占位符段落位置插入表格，然后移除占位符段落。用户可直接替换模板文件，只要保留上述占位符即可。

#### 占位符替换范围

占位符替换方法（`replaceProfilePlaceholders()`、`replaceExtractDataPlaceholders()`）通过 `forEachParagraph()` 遍历文档中**所有段落**，包括：

- 文档顶层段落（`doc.getParagraphs()`）
- **表格单元格内的段落**（遍历 `doc.getTables()` 中每个单元格的段落）

因此占位符可以放在模板中任意位置：**普通段落**或**表格单元格**内均可正常替换。

#### 字体样式保留

占位符替换采用**段落级拼接替换 + 复用第一个 run** 的策略（`replaceParaTextPreserveStyle()`）：

1. 先通过 `para.getText()` 在段落级别拼接所有 run 的文本，避免占位符被 Word 拆分成多个 run 时无法匹配
2. 在拼接文本中替换占位符，仅清理段落 run 之间可能残留的换行符
3. 替换结果**写入段落的第一个 run，删除其余 run**，从而完整保留第一个 run 的字体样式（字体、字号、加粗、颜色等）

**换行处理**：替换值内部的换行符（`\n`）会转换为 Word 软换行元素（`<w:br/>`），使多行文本（如商业计划书多条记录以换行连接的提取文本）在报告中正确显示为多行，而非被 Word 折叠为空格。

> **模板制作建议**：占位符段落的字体样式以**第一个 run** 为准。若需为替换结果设置特定字体，请确保该段落第一个 run 已应用相应格式（如通过 Word 给占位符段落设置"仿宋"、字号 15 等）。

> **空数据清空**：当无财务数据时，`{{balance_sheet_key_items}}` / `{{profit_sheet_key_items}}` 占位符通过 `clearPlaceholderText()` 替换为空字符串（不插入表格）。

### Service 分层

| 接口                   | 实现                       | 职责                              |
| -------------------- | ------------------------ | ------------------------------- |
| `SxdService`         | `SxdServiceImpl`         | 材料上传、提交、附件管理、实控人确认、提取状态轮询       |
| `ExtractDataService` | `ExtractDataServiceImpl` | 提取数据查询+缓存、xlsx/zip 导出、Word 报告生成 |

> 报告生成由 `ExtractDataService.generateReport()` 实现，商业计划书提取文本从 `kjjr_ai_sxd_extract_data` 缓存表读取。

报告里四类"由大模型撰写"的内容，各有自己的生成器，共用同一套调用与降级骨架：

| 类                                                | 职责                                                                                                                                        |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `service/sxd/support/LlmSectionWriter`           | **公共执行器**：读提示词并缓存、调模型、规整输出（`write` 单段折平 / `writeMultiline` 保留换行）、**任何失败一律留空**。所有"生成式段落"都走它，保证降级口径只有一处                                     |
| `service/sxd/support/BusinessProfileSummarizer`  | 拼 7 段 BP 提取材料（共用 `BpExtractSources.SOURCES`）→ 委托 `LlmSectionWriter` 生成「客户基本概况」四字段（主营业务概况 / 下游主要服务 / 企业亮点描述 / 专利技术应用情况及创投投资情况），**一次调用出五行** |
| `service/sxd/support/BusinessOverviewSummarizer` | 拼 7 段 BP 提取材料（共用 `BpExtractSources.SOURCES`）→ 委托 `LlmSectionWriter` 生成「企业主营业务情况」                                                          |
| `service/sxd/support/AbnormalFinanceDescriber`   | 接收已筛好的超阈值科目清单 → 委托 `LlmSectionWriter` 生成「异常财务数据说明」                                                                                        |
| `service/sxd/support/DirectorResumeSummarizer`   | 拼人员简历 + 实控人姓名 → 委托 `LlmSectionWriter` 生成「实际控制人及团队简介」（多行）                                                                                  |

> **AI 调用一律走 `LlmClient` 门面**：上述类注入的是**接口** `LlmClient`，运行时由 Spring 装配到 `LlmClientImpl`；全项目只有 `LlmClientImpl` 一个类引用 Spring AI 类型（`ChatClient` / `OpenAiChatOptions`）。**新增 AI 调用请在 `LlmClient` 上加方法、不要在业务类里直接发 HTTP 或注入 `ChatClient`。** 这样将来换成调用**自定义模型**时，只需：① 网关仍是 OpenAI 兼容协议 → 改 `spring.ai.openai.base-url` / `api-key` / `chat.options.model`，代码零改动；② 协议不同 → 新写一个 `LlmClient` 实现（记得给默认那个加 `@Primary`，否则注入处会 `NoUniqueBeanDefinitionException`），业务类同样零改动。

## 六、配置项

```properties
# 外部表格提取状态接口地址（不含 docId，调用时拼接）
dib.doc-table-extract-state-url=${dib.base-url}/api/extract/open/doc/docTableExtractState
# 外部文档删除接口地址（不含 docId，调用时拼接）
dib.doc-delete-url=${dib.base-url}/api/extract/open/doc/delete

# Word 报告模板文件路径（必需项，支持 classpath: / file: 前缀）
report.template-path=classpath:templates/sxd/report-template.docx

# 大模型提示词路径【不需要写在这里】：默认值已经在各段落生成器的 @Value 里，见下表。
# 要临时改某一段，在外面加 report.<段落>-prompt-path= 覆盖即可。
```

| 属性                                     |   必需  | 说明                                                                                 |
| -------------------------------------- | :---: | ---------------------------------------------------------------------------------- |
| `dib.doc-table-extract-state-url`      |   是   | 表格提取状态接口基地址，调用时在末尾拼接 `/{docId}`                                                    |
| `dib.doc-delete-url`                   |   是   | 文档删除接口基地址，调用时在末尾拼接 `/{docId}`                                                      |
| `report.template-path`                 | **是** | 报告模板路径。`@Value` **没有默认值**，缺这个键会直接**启动失败**（模板是报告必需品）。支持 `classpath:` 和 `file:` 外部路径 |
| `report.business-overview-prompt-path` |   否   | 「企业主营业务情况」提示词路径，默认 `classpath:templates/sxd/business-overview-prompt.txt`          |
| `report.abnormal-finance-prompt-path`  |   否   | 「异常财务数据说明」提示词路径，默认 `classpath:templates/sxd/abnormal-finance-prompt.txt`           |
| `report.director-resume-prompt-path`   |   否   | 「实际控制人及团队简介」提示词路径，默认 `classpath:templates/sxd/director-resume-prompt.txt`          |
| `report.business-profile-prompt-path`  |   否   | 「客户基本概况」四字段提示词路径，默认 `classpath:templates/sxd/business-profile-prompt.txt`          |

> **为什么那 4 条提示词路径不必写进 `application.properties`**：它们的 `@Value` 表达式本身就带默认值（`${report.xxx-prompt-path:classpath:...}`），配置行与默认值逐字相同 —— 同一个值写两处，迟早改一处忘一处（这两处一度就不一致：配置注释还写着"三字段"，实际早已是四字段）。删掉配置行后覆盖能力一点不少，已用 `_scratch/PromptPathOverrideProbe.java` 逐条验证：
>
> - 不配任何值 ⇒ 取 `@Value` 默认值（4 条全对）
> - 挂外部 config 文件（容器 WORKDIR 下的 `config/application.properties`）⇒ 只覆盖指定的那个键，其余不受影响
> - 设环境变量 `REPORT_ABNORMAL_FINANCE_PROMPT_PATH` ⇒ 被宽松映射到 `report.abnormal-finance-prompt-path` 并生效
>
> ⚠️ **不要把它们写成空值**（`report.xxx-prompt-path=`）：空串会**顶掉** `@Value` 默认值，结果是该段落静默变空（只有一行 ERROR），而不是回落默认值。这个坑是"键存在"才有的 —— 不写这个键反而不会踩。
>
> ⚠️ 4 条提示词路径的**文件缺失/为空/读不出来都不会导致应用启动失败**：报告里对应段落留空并打 ERROR 日志（「客户基本概况」那四个占位符则是回落成兜底句式）。

> **提示词调优**：4 个提示词文件就是各段落的写作要求，直接改文本即可，**不需要重新编译**；但应用只在**启动时读一次并缓存**，所以**改完要重启**才生效。以下只举两例 —— 企业主营业务情况要求"忠于材料、数字不得改写、缺项省略、商业模式与盈利模式不重复、输出一段连续文字、不超过 600 字"；异常财务数据说明要求"逐科目一行、数字照抄、比率类科目写成'由 X% 升至 Y%'、只写变化不说原因"。
>
> ⚠️ **不要给这次调用设 `maxTokens`**：`deepseek-flash` 带思考链，**思考 token 也计入这个上限**。实测同一份输入取 2000 时思考就把额度吃满、**正文返回为空**（报告里该段落会被留空）；不设则沿用服务端默认，正常出正文。若将来确实需要全局限制生成长度，请在 `spring.ai.openai.chat.options.max-tokens` 里配，不要写进代码。
>
> **耗时提醒**：报告接口现在有**四次**大模型调用，**串行**执行，顺序为：客户基本概况四字段 → 实际控制人及团队简介 → 企业主营业务情况 → 异常财务数据说明。这条链路的超时受全局 `spring.ai.retry.*` 与 `spring.http.client.read-timeout` 约束，最坏阻塞 ≈ `4 ×（max-attempts × read-timeout + 退避）`，会叠加到报告接口的总耗时上（网关 `proxy_read_timeout` 为 60s）。若线上出现报告超时，优先从这里排查。异常财务数据说明那一次的输出较长（实测 12 个科目约 1.4k 字、含约 3k 思考 token），耗时也更长。

> 其他共享配置（`dib.doc-query-data-url`、`dib.c1-api-key` 等）参见[要素提取功能说明](要素提取功能说明.md#六配置项)。

## 七、错误码

| 错误码                  | 触发条件                                           | HTTP 状态码 |
| -------------------- | ---------------------------------------------- | -------- |
| `TASK_NOT_FOUND`     | `taskId` 在 `kjjr_ai_sxd_record` 表中不存在          | 400      |
| `CST_ID_MISMATCH`    | 传入的 `cstId` 与 `kjjr_ai_sxd_record` 中记录的客户编号不一致 | 400      |
| `DOC_NOT_FOUND`      | `taskId` 在 `kjjr_ai_sxd_doc` 表中无关联的财务报表记录      | 400      |
| `TABLE_STATE_FAILED` | 外部表格提取状态接口调用失败（网络异常 / 非成功响应）                   | 400      |
| `DOC_QUERY_FAILED`   | 外部提取数据查询接口（资产负债表或利润表）调用失败                      | 400      |
| `TEMPLATE_NOT_FOUND` | 模板文件不存在（检查 `report.template-path` 路径）          | 400      |
| `DOC_CREATE_FAILED`  | Word 文档生成异常（POI 写入失败）                          | 400      |

> **大模型相关失败不占错误码**：四处大模型生成（客户基本概况四字段、实际控制人及团队简介、企业主营业务情况、异常财务数据说明）的任何失败（提示词不可用、调用超时/报错、返回空内容）都在 `LlmSectionWriter` 内部消化为**该段落留空**，报告照常返回，只打 ERROR 日志。这是刻意设计——报告本身是交付物，这几段只是排版增强，不该因一次模型抖动让整份报告生成失败；同时也不退化成"原文拼接"，因为未经整理的原文塞进报告观感更差。若希望改为"失败即报错"，去掉 `LlmSectionWriter#generate` 里的 `catch` 即可。**注意：留空在报告里是静默的，ERROR 日志是发现异常的唯一信号，别把这几条日志删掉。**

GET /extract-status/{taskId}
  → completed=true

                                    → queryData(利润表) → 获取科目
                                    → 大模型生成（BP 7 段提取文本 → 客户基本概况四字段）
                                    → 大模型二次总结（人员简历 + 实控人姓名 → 实际控制人及团队简介）
